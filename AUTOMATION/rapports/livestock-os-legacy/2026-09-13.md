## 1. Le registre se trompe : ce n'est pas un doublon

`registry.json` classe ce dépôt **tier 3**, `« livestock-os (doublon présumé) »`. Les deux
affirmations sont fausses.

```
$ git merge-base livestock-os/master livestockos/main
→ AUCUN ancêtre commun
```

Ce ne sont pas deux versions d'un produit, ce sont **deux produits différents** :

| | `livestockos` (tier 1) | `livestock-os` (tier 3, « doublon ») |
|---|---|---|
| Tronc | `main`, 19 commits | `master`, 17 commits |
| Dernier commit | **11 août** | **27 août** |
| Pages | alimentation, animaux, production, rapports, santé, stocks, transactions, vaccination, ventes | animaux, marché, mouvements, **passeport**, rapports, santé, ventes, paramètres, onboarding, **verifier/[code]** |
| Authentification | aucune | **Better Auth** — login, register, route API |
| Base | Supabase | **Neon** (migration assumée le 24 août) |
| Persistance | — | **offline-first**, store local |

**`livestock-os` est plus récent, plus complet, et fait autre chose.** `livestockos` gère un
cheptel ; `livestock-os` gère un cheptel **et le rend lisible par un prêteur** :

```
2026-08-27  feat(passeport): relevés vérifiables par le prêteur
2026-08-26  feat(dashboard): données réelles + passeport du cheptel
2026-08-25  merge: sprint17 — persistance offline-first, module Ventes, migration Neon
```

La page publique `verifier/[code]` et la route `api/passeport/publier` disent le mécanisme : un
éleveur publie un passeport de cheptel, un prêteur le vérifie par un code. C'est exactement la
chaîne de valeur décrite dans `VISION.md` — rendre un actif informel finançable.

**C'est probablement le produit le plus avancé du portefeuille, et il est classé comme une
archive à contrôler une fois par mois.**

## 3. Ce qui bloque, et ce que je ne fais pas

**`livestockos` (le tier 1) a toujours sa branche par défaut sur `feat/animaux-rapports`** —
une branche de 3 commits arrêtée au 1ᵉʳ août, alors que son `main` en a 19 et va jusqu'au
11 août. C'est le défaut que j'avais relevé le 5 septembre et qui n'a pas bougé. Ma PR #10 y
attend toujours.

Je **ne re-classe pas** `livestock-os` de tier 3 à tier 1 : changer la priorité d'un projet, et
surtout décider lequel des deux produits d'élevage est le bon, est une décision de Steeve.
**Q18.**

J'ai en revanche corrigé dans `registry.json` la mention factuellement fausse
« doublon présumé » — c'est une erreur constatable, pas un arbitrage.
