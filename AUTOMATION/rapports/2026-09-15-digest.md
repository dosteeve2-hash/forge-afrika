## 🔴 `binary-search-tree-java` — la branche de nettoyage ne compile pas

Hier, sur `Mon-Portfolio-`, une branche `chore/cleanup` était juste et je l'ai
recommandée à la fusion. Ici la branche porte le **même nom**, vient de la **même
campagne du 11 juin**, et elle est **cassée**.

Son intention est bonne : sur `main`, tout le projet tient dans un **ZIP** — pas de diff,
pas de `git blame`, pas de recherche, plus les `.class` compilés et une copie imbriquée.
La branche extrait les sources dans `src/`, écarte les artefacts, translittère un nom de
fichier turc. Tout cela est bien fait.

Mais le ZIP contenait **deux `TreeGUI.java` divergents**, et elle a pris le mauvais — le
plus récent, qui a une accolade en trop et appelle `new TreeGUI()` **sans
`setVisible(true)`**, que le constructeur n'appelle pas davantage.

Compilé, les deux :

```
version de chore/cleanup   → TreeGUI.java:179: error: class, interface, enum,
                              or record expected                        code 1
copie imbriquée du ZIP     →                                            code 0
```

La fusionner transformerait un dépôt dont le projet fonctionne en un dépôt dont le code
visible ne compile pas. `main` n'est pas cassé : le ZIP qu'il contient renferme une
version saine. **Rien poussé, rien corrigé** — la correction tient en un geste, décrit
dans le rapport.

**Règle 19.** Une branche du même nom, issue de la même campagne, peut être juste sur un
dépôt et fausse sur son voisin. La seule façon de savoir est de l'exécuter.

## 🟡 `Donald` — sain, mais ce n'est pas un projet

Trois fichiers, aucun secret, dormant depuis le **25 octobre 2025** — le plus dormant du
portefeuille. Un README d'**une ligne** (`# Donald`), un devoir de développement web en
**archive RAR** de 1,7 Mo, et un script Python de contrôle par gestes de la main. Deux
travaux sans rapport, dans un dépôt dont le nom ne dit rien.

Le script importe `cv2` et `mediapipe` sans aucun fichier de dépendances — or MediaPipe
casse souvent entre versions.

## Le motif du matin

**Deux des quatre dernières archives livrent leur code dans un fichier compressé** — un
ZIP, un RAR. Ce n'est pas un accident. Le RAR est en plus propriétaire : aucun outil ne
l'ouvrait dans ma session, ce qui illustre le problème mieux qu'un argument.
