## Le même défaut qu'ailleurs ce matin : du code en archive

`WebOdev1_SteeveDo.rar` est un `RAR v5`. Comme le ZIP de `binary-search-tree-java`, c'est
du code qu'on ne peut ni lire, ni diffuser, ni chercher depuis git. Je n'ai pas pu
l'ouvrir : aucun outil RAR n'est disponible dans cette session — ce qui illustre le
problème mieux qu'un argument. Le format RAR est propriétaire et n'est pas lisible
partout, contrairement au ZIP.

**Deux des quatre dernières archives du portefeuille livrent leur code dans un fichier
compressé.** C'est un motif, pas un accident.

## 🟠 Le script Python n'a pas de quoi être exécuté

`hand_gestures_effects.py` importe `cv2` et `mediapipe`. Le dépôt ne contient **ni
`requirements.txt`, ni `pyproject.toml`, ni `Pipfile`**. Quiconque le clone — y compris
Steeve dans six mois — doit deviner les dépendances et leurs versions ; or MediaPipe est
précisément une bibliothèque dont les versions cassent souvent entre elles.

Le script est propre par ailleurs : il vérifie que la caméra s'ouvre et sort proprement
sinon, messages en français.

## Recommandation

Par ordre de coût croissant, aucune urgente :

1. **Écrire deux lignes de README** disant ce que le dépôt contient. C'est le geste le
   moins cher et le plus utile — aujourd'hui, seul Steeve peut savoir ce qu'est `Donald`.
2. **Ajouter un `requirements.txt`** (`opencv-python`, `mediapipe`) si le script doit
   rester exécutable.
3. **Extraire le RAR** et versionner les sources, ou l'archiver ailleurs — un devoir
   rendu n'a pas forcément vocation à rester dans un dépôt public.
4. Ou **fusionner ce dépôt** avec un autre : seul, il ne représente rien dans le
   portefeuille.

L'étiquette du registre (tier 3, archive) est **juste** : dormant depuis 11 mois, aucun
lien avec la Phase 1.
