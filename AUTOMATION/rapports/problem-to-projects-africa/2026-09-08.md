## 1. Le dépôt contient deux applications sans aucun lien de parenté

C'est le quatrième dépôt du portefeuille avec des troncs divergents — après `forge-afrika`,
`comptrack` et `livestockos`. Mais celui-ci est d'une autre nature :

```
$ git merge-base origin/main origin/master
→ aucun ancêtre commun
```

**`main` et `master` ne partagent pas un seul commit.** Ce ne sont pas deux versions d'une même
application qui ont divergé : ce sont deux applications différentes, construites séparément, dans
le même dépôt. Aucune fusion git n'est possible entre elles — il n'y a rien à quoi se rattacher.

| | `main` (branche par défaut) | `master` |
|---|---|---|
| Commits | 32 | 7 |
| Dernier commit | 25 juillet | 13 juillet |
| Fichiers | 105 | 80 |

Les deux ont un `dashboard`, un `login`, un `auth/callback` — écrits deux fois, séparément.

**Et les deux PR ouvertes visent des troncs différents** : la #10 vise `main`, la #9 vise
`master`. Le travail continue en parallèle sur les deux branches, sans que rien ne les relie.

C'est la question **Q13**. Je n'ai rien touché : choisir laquelle des deux applications est le
produit est une décision de Steeve, et elle est irréversible pour l'autre.

## 2. `main` : ça compile, mais rien ne le vérifie

Vérifié en local sur la branche par défaut telle quelle :

| Contrôle | Résultat |
|---|---|
| `npm run build` | **passe** — 18 routes |
| `npx eslint .` | 0 erreur, **91 avertissements** |
| `npx tsc --noEmit` | **échoue** |
| CI | **aucune** — pas de dossier `.github` |

Trois choses méritent d'être nommées :

**Deux `@ts-nocheck`**, dont un sur `src/lib/recommendation/enhanced-engine.ts` — le moteur de
recommandation, c'est-à-dire le cœur du produit. TypeScript y est entièrement désactivé. Le
second est sur `src/components/intake/differentiated-intake-forms.tsx`.

**Un fichier de tests que rien ne peut exécuter.** `src/__tests__/components.test.tsx` existe,
mais `package.json` n'a **aucun script `test`** et aucun runner installé. D'où l'échec de `tsc` :

```
src/__tests__/components.test.tsx(118,5): error TS2582: Cannot find name 'it'.
src/__tests__/components.test.tsx(120,7): error TS2304: Cannot find name 'expect'.
```

Un fichier de tests qui ne compile pas et ne s'exécute pas donne l'apparence d'une couverture
sans en offrir aucune. C'est pire que pas de test du tout : ça trompe le lecteur.

**Aucune CI**, donc rien n'a jamais signalé les deux points ci-dessus.

masquait, et il faut ensuite les corriger vraiment. C'est ce que fait le gros du diff —
`transformation-engine.ts` (+122), `enhanced-engine.ts` (+67), `enhanced-intake-form.tsx` (+54),
`supabase-client.ts`, `sync-service.ts`.

**Recommandation : fusionner la #10.** Elle est construite sur le `main` d'aujourd'hui, elle est
verte, et elle apporte la CI qui empêchera la situation de se reproduire.

## 6. Ce que je recommande, par ordre

1. **Trancher Q13** — `main` ou `master` ? Tout le reste en dépend.
2. **Fusionner la #10** si la réponse est `main` (vérifiée verte, base à jour).
3. **Fermer la #9** dans ce cas — elle porte sur l'application abandonnée.
4. **Récupérer de `master` ce qui n'existe nulle part ailleurs** avant de l'archiver :

   suppression d'une branche ne m'appartient pas (protocole §3, règle 4).

## 7. Pourquoi je n'ai rien construit

Deux PR seulement, donc le seuil de triage ne s'appliquait pas — j'aurais pu développer. Je ne
l'ai pas fait pour une raison simple : **je ne sais pas laquelle des deux applications est le
produit.** Écrire du code sur `main` avant que Q13 soit tranchée, c'est risquer de développer
celle qui sera abandonnée. C'est exactement l'erreur que le portefeuille répète depuis juin.
