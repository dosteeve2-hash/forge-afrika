## Sahel Commerce AI — un endpoint ouvert qui écrit en base

```python
@router.post("", response_model=ChatOut)
def chat(payload: ChatIn) -> ChatOut:
    return ChatOut(**run_agent(payload.message))
```

Ni authentification ni limite. Et l'agent derrière dispose d'outils qui **écrivent** :
`add_product`, `adjust_stock`, `record_sale`, `reconcile_momo`.

Deux conséquences, la seconde étant la pire : **le crédit d'API peut être vidé** — ça se voit sur
une facture — et **le stock d'un commerçant peut être modifié, de fausses ventes enregistrées** —
ça ne se voit pas, sur un outil censé tenir la comptabilité d'une boutique.

Ce qui était correct, et que j'ai vérifié avant de chercher ailleurs : le prompt système est une
constante, le message utilisateur entre comme tour `user` séparé. La règle d'injection du
`CLAUDE.md` est respectée.

**PR #1** — compteur à fenêtre fixe, en mémoire, **sous verrou** (uvicorn sert les endpoints
synchrones dans un pool de threads ; sans verrou, deux requêtes simultanées n'incrémentent qu'un
compteur). Aucune dépendance ajoutée : `render.yaml` est mono-instance, et le jour où il y aura
plusieurs répliques, seul l'intérieur de `etat_quota()` changera — c'est écrit dans le module.

Le dépôt n'avait **aucun test**. La PR en ajoute 12, éprouvés comme au Portfolio : en retirant la
dépendance, **2 échecs** ; en la remettant, **12/12**. Plus la première CI du dépôt.

**Ce que je n'ai pas fait : l'authentification.** C'est le vrai manque — une limite borne l'abus,
elle ne dit pas *qui* modifie le stock. Décision d'architecture, pas correctif. **Q16.**

## UEEMT-Tokat — le tronc ne se construit pas sans secrets

```
$ npm run build
✓ Compiled successfully
Error: Missing API key. Pass it to the constructor `new Resend("re_123")`
> Failed to collect page data for /api/onboarding
```

`src/lib/email.ts` construisait le client Resend **au chargement du module**. `new Resend()` lève
quand la clé manque, donc le build s'arrête. **Aucune CI ne peut construire ce dépôt**, et aucun
contributeur sans clé de production non plus. Avec 131 erreurs de lint par-dessus.

La **PR #14** corrige tout — vérifiée : **131 → 0** erreurs, build **38 pages**, 24 tests
inchangés. Le correctif est le bon geste : une fabrique appelée au besoin plutôt qu'une constante
de module.

Et **quatre des sept PR visent `dev`, pas `main`** — le motif de CompTrack. `dev` est-elle encore
une branche d'intégration ou un vestige ? **Q17.**
