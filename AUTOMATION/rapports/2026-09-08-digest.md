## Les deux défauts

**ValueChain Connect.** Le total estimé d'un devis se calcule depuis deux champs de saisie
libre. `Number('12,5')` vaut `NaN` — et **un utilisateur francophone tape la virgule**.
Il lisait « NaN FCFA » comme total de son devis. Et `10.5 × 333` affichait « 3 496,5 FCFA »,
des centimes sur une monnaie qui n'en a pas.

**Indubot Afrika.** Un `Intl.NumberFormat(undefined, …)` demandait la locale de
l'environnement : celle du serveur au rendu, celle du navigateur à l'hydratation. Sur une
application rendue côté serveur, c'est une divergence d'hydratation — pas un détail de style.

Les deux dépôts avaient **zéro test**. Ils en ont vingt à eux deux, et leur CI les exécute.

## Quatrième projet — MillTrack, et la démonstration par les jumeaux

MillTrack n'a que 3 PR ouvertes : sous le seuil, donc construction autorisée.

Premier réflexe, tout neuf depuis FORJA : **vérifier le tronc avant de brancher**. Il est sain —
lint 0, 124 tests, build 13 routes, CI présente.

Et là se joue la démonstration de la journée. Le 2 septembre, MillTrack a **fusionné** sa PR #12,
*« répare 7 tests, 21 erreurs de lint et ajoute la CI »*. Le même jour à quelques heures près,
FORJA a reçu sa PR #27, *« répare 5 tests, 12 erreurs de lint et ajoute la CI »* — **toujours
ouverte**. Deux dépôts jumeaux, le même correctif, deux destins : l'un a un tronc vert et une CI,
l'autre est rouge depuis un mois sans que rien ne le signale. Le goulot n'est pas dans l'écriture
du correctif. Il est dans le geste de fusionner.

**Ce que j'ai construit — PR #13.** Le tableau de bord était inutilisable sur la cible de
`VISION.md §4`, un Android de 360 px : barre latérale de 256 px sans aucun point de rupture
(`grep -c "md:\|sm:"` sur le layout → **0**), donc **104 px de contenu** ; trois tableaux de 8 à
10 colonnes sans conteneur défilant, qui emportaient la page entière, titres et navigation
compris ; neuf grilles de KPI figées à 3 ou 4 colonnes.

Barre latérale au-dessus de 768 px, tiroir en dessous — animé en CSS et non avec framer-motion,
parce que sur un téléphone d'entrée de gamme en 2G/3G chaque kilo-octet de JavaScript se paie. Le
layout redevient au passage un Server Component : il était `'use client'` en entier pour rendre
une liste de liens statique.

**146 tests (124 avant), lint 0 erreur 0 avertissement, build 13 routes.**

Une règle de lint m'a fait écrire *moins* de code : `react-hooks/set-state-in-effect` a refusé le
`useEffect(() => setOuvert(false), [pathname])` évident, et la correction — mémoriser le chemin
d'ouverture plutôt qu'un booléen — supprime l'effet entier. Et un de mes tests avait tort là où le
composant avait raison : un tiroir en `aria-hidden` sort de l'arbre d'accessibilité, donc ses
liens ne doivent **pas** être comptés.

## Cinquième projet — African Hybrid Agent, et le triage qui se retourne

Sixième dépôt de la journée, 6 PR ouvertes, donc triage. Et il a renversé la règle que je venais
d'établir.

**Le tronc n'a pas bougé depuis le 27 juin** — 73 jours. Conséquence : contrairement à FORJA,
**aucune des 6 PR n'est périmée.** Cinq sont à zéro commit de retard. Il n'y a rien à fermer :
il y a six PR encore bonnes et personne pour les fusionner.

**Pourquoi ce dépôt est figé.** Sa CI n'a *jamais* pu passer, pour trois raisons indépendantes :
`node-version: '18'` alors que Next 16 exige ≥ 20 ; `actions/upload-artifact@v3`, désactivée par
GitHub depuis janvier 2025 ; et un `coverageThreshold` global à 50 % quand la couverture réelle
est de 19,98 % — donc `npm test` sortait en code 1 même avec 50 tests au vert. Ce n'est pas une
CI instable, c'est une CI qui ne pouvait pas réussir.

**Troisième dépôt où le même correctif attend.** MillTrack #12 : fusionnée le 2 septembre, tronc
vert. FORJA #27 : ouverte, tronc rouge depuis un mois. African Hybrid Agent #7 : ouverte, tronc
figé depuis 73 jours. Trois fois la même PR, trois destins, un seul geste manquant.

**⚠️ Ici, la PR qui attend borne une dépense.** `/api/chat` n'a ni limite de débit ni
authentification sur `main`, et `src/lib/llm/generate.ts` route vers Anthropic ou OpenAI dès
qu'une clé est définie. Le dépôt est public. **Je n'ai pas vérifié s'il existe un déploiement
avec une clé** — lire les variables d'environnement d'un déploiement est une action de
production, hors de mes limites. C'est la question **Q11**, et si la réponse est « oui », elle
coûte de l'argent chaque jour. Rien n'est exposé côté secrets, en revanche : vérifié, aucun
`.env` versionné, aucune clé dans l'arbre.

**La #7 mérite d'être reprise, pas fusionnée telle quelle** : le limiteur lui-même est bon
(Redis avec repli mémoire, `429` + `Retry-After`, 98 lignes de tests), mais la PR versionne tout
le dossier `coverage/` — **39 124 lignes ajoutées pour ~240 utiles** — et son `.gitignore` ajoute
`*.tsbuildinfo` sans ajouter `coverage/`.

**La leçon, qui corrige celle du matin.** La bonne question de triage n'est pas *« combien de PR
ouvertes ? »* mais *« le tronc a-t-il bougé ? »*. Tronc qui avance sans ses PR : elles
pourrissent, il faut fermer. Tronc arrêté : elles restent bonnes, il faut fusionner. Même cause —
personne ne fusionne — mais remède opposé. Un loop qui ne regarde pas la date du dernier commit
du tronc se trompera de remède.

## Sixième projet — BurkinaCollect, ou la PR en brouillon qui contient tout

Deux PR ouvertes seulement, donc sous le seuil de triage. **Je n'ai pourtant rien construit**, et
c'est la décision la plus nette de la journée.

```
$ git ls-tree -r --name-only origin/main
README.md
hooks/useOfflineSync.ts
```

**La branche par défaut de ce dépôt public contient deux fichiers.** Toute l'application — 17
fichiers, Next.js 16 — vit dans la PR **#4**, ouverte le 2 septembre et laissée **en brouillon**.

Et le README de `main` présente un produit fini : badges, un lien « Voir le site live », et six
fonctionnalités — dashboard opérationnel, form builder, sync queue, gestion des agents, carte des
zones, dashboard superviseur. **Aucune des six n'existe dans aucune branche** ; la plus avancée a
deux routes, `/` et `/about`. Le README affiche même son logo via `public/favicon.ico`, absent de
`main` : le logo est cassé sur la page GitHub. `PROJECT.md` dit que *« déployé sur Vercel » n'est
pas « utilisé par une entreprise réelle »* ; ici on est un cran avant — *« annoncé dans un
README » n'est pas « déployé »*. C'est la question **Q12**, et elle est ta parole, pas la mienne.

**⚠️ Le seul code de `main` perd des données terrain, en silence.** Dans `useOfflineSync.ts`, un
item qui a épuisé ses `MAX_RETRIES` n'entre dans aucune branche du `if`, donc il n'est pas
repoussé dans `remaining` — et `remaining` écrase la file dans `localStorage`. En clair : un
agent remplit un formulaire hors réseau, trois synchronisations échouent, **sa saisie disparaît
et rien ne le lui dit**. `VISION.md §4` : *« la coupure en plein formulaire est un cas nominal,
pas un cas limite »*. Un outil de collecte offline-first qui perd une saisie en silence ne rate
pas un détail, il rate sa raison d'être.

**La PR #4 corrige exactement cela** — `processQueue()` extraite en fonction pure, trois issues
au lieu de deux (`synced` / `remaining` / **`failed`**), les items épuisés remontant au hook au
lieu d'être effacés. Vérifiée en local : **lint 0, 6/6 tests (il n'y en avait aucun), build 3
routes**. Elle apporte aussi la CI que le dépôt n'a pas. La #3 est absorbée par elle.

**La leçon.** Une PR en brouillon est invisible : personne ne la relit, aucun bot ne l'annote,
elle ne demande rien à personne. C'est le bon défaut pour *mes* PR — il rend mon travail
réversible. C'est un piège quand la PR **est** le livrable principal du dépôt. Six jours qu'une
application entière attend derrière un statut.
