# AgroTrack BF — 16 septembre 2026

## Ce qui a été trouvé

`https://agrotrack-bf.vercel.app/dashboard` répond **HTTP 500**. Vérifié ce matin à
02h19 UTC via `web_fetch_vercel_url`. Le relevé du **22 août** signalait déjà la même
panne : **vingt-cinq jours**.

Vercel `get_runtime_errors` ne remonte rien sur 24 h — l'agrégation ne voit pas cette
erreur. J'ai donc **reproduit** plutôt que déduit : application lancée localement sans
les deux variables Supabase.

```
GET /            → 200
GET /dashboard   → 500
serveur : Error: Your project's URL and Key are required to create a Supabase client!
```

Deux occurrences, layout et page — correspondant aux deux digests de la production
(`527092414`, `918475680`).

## La cause

`lib/supabase/client.ts` et `server.ts` écrivaient `process.env.X!`. L'assertion ne ment
qu'au vérificateur de types ; à l'exécution la variable vaut `undefined` et c'est
`@supabase/ssr` qui lève — **dans `createClient()`**, donc **avant** que le layout ait pu
appeler `getUser()` et rediriger. Une variable oubliée ne dégradait pas la connexion :
elle emportait les **seize** pages du tableau de bord.

## Ce qui a été livré — PR #19

`lib/supabase/config.ts` détecte au lieu d'asserter et rend des replis syntaxiquement
valides. Le layout teste avant de construire le client et redirige vers
`/auth/login?raison=non-configure`. La page de connexion dit ce qui manque et désactive
le bouton de démo. Les deux Server Actions revalident pour elles-mêmes.

`||` et non `??` : une variable **définie mais vide** est la façon la plus courante de
désactiver une variable chez un hébergeur — un test verrouille ce cas.

### Prouvé dans les deux sens

| sans variables | avant | après |
|---|---|---|
| `/dashboard` | **500** | **307** → `/auth/login?raison=non-configure` |
| `/membres` | 500 | 307 |
| `/auth/login` | 200 | 200, bannière affichée |
| `URL and Key are required` au journal | 2 | **0** |

Avec variables, non connecté : `/dashboard` → 307 vers `/auth/login` **sans** `?raison=`,
et **aucune** bannière. Pas de faux positif.

Lint 0 erreur · tests **120 → 125** · build vert.

## Règle 23

- **23a — authentification : PASSE.** `app/(dashboard)/layout.tsx` appelle `getUser()`
  côté serveur et redirige ; les seize pages vivent sous ce layout. C'était ma première
  hypothèse et **elle était fausse** — vérifiée avant d'être écrite. Le compte du motif
  reste à quatre.
- **23b — mouvement piloté en JS : PASSE.** Aucun `gsap`, `lenis` ni
  `requestAnimationFrame` dans le dépôt.
