## livestock-os — le registre se trompe depuis le début

Ce dépôt est classé **tier 3**, avec la mention *« doublon présumé »*. Les deux affirmations sont
fausses.

```
$ git merge-base livestock-os/master livestockos/main
→ AUCUN ancêtre commun
```

Ce ne sont pas deux versions d'un produit. `livestockos` gère un cheptel.
**`livestock-os` le rend lisible par un prêteur** : `dashboard/passeport`,
`api/passeport/publier`, et une page publique `verifier/[code]` — un éleveur publie un passeport
de cheptel, un prêteur le vérifie par un code.

```
2026-08-27  feat(passeport): relevés vérifiables par le prêteur
2026-08-25  merge: sprint17 — persistance offline-first, module Ventes, migration Neon
```

Il est **plus récent** (27 août contre 11), il a une **authentification** (Better Auth) que
l'autre n'a pas, il a migré vers Neon, et il est **offline-first** — la doctrine terrain, pour de
vrai. C'est littéralement la chaîne de valeur de `VISION.md` : rendre un actif informel
finançable.

**Le produit le plus avancé du portefeuille est classé comme une archive à contrôler une fois par
mois.** C'est **Q18**.

Le dépôt lui-même est sain : privé, déployé, aucun secret versionné, branche par défaut
cohérente. J'ai corrigé dans `registry.json` la mention « doublon présumé » — c'est une erreur
constatable, pas un arbitrage. **Je n'ai pas changé le tier** : décider lequel des deux produits
est le bon t'appartient, et développer le mauvais serait la pire dépense du portefeuille.
