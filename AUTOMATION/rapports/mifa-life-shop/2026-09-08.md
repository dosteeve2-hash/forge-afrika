## 1. Le tronc ne s'installe pas

```
$ npm ci
npm error `npm ci` can only install packages when your package.json and
npm error package-lock.json are in sync.
npm error Missing: webpack@5.110.3 from lock file
npm error Missing: @testing-library/dom@10.4.1 from lock file
npm error Missing: aria-query@5.3.0 from lock file      (… et 8 autres)
```

Ce n'est pas un détail de confort. `npm ci` est ce qu'exécutent les CI et les plateformes de
déploiement : tant que le verrou est désynchronisé, **aucune intégration continue ne peut
installer ce dépôt**, et quiconque le clone n'obtient pas l'arbre de dépendances attendu. C'est
le tronc le plus cassé des sept dépôts de la série du 2 septembre.

## 2. Le seul workflow du dépôt échoue à chaque push

`.github/workflows/azure-webapps-node.yml` est le **modèle fourni par GitHub**, laissé tel quel —
son en-tête contient encore la notice d'installation :

> *« 1. Download the Publish Profile for your Azure Web App… 2. Create a secret named
> `AZURE_WEBAPP_PUBLISH_PROFILE`… 3. Change the value for `AZURE_WEBAPP_NAME` »*

Aucune de ces trois étapes n'a été faite, et il se déclenche `on: push: branches: [main]`. Il
échoue donc à chaque push depuis qu'il existe. Le dépôt a l'apparence d'une CI et n'en a aucune :
rien ne fait tourner le lint, les tests ou le build — et c'est ce qui a laissé le verrou
diverger sans que personne ne le voie.

Il n'y a par ailleurs **aucun déploiement Azure** dans ce projet : `vercel.json` et
`netlify.toml` sont à la racine. Le workflow ne sert à rien d'autre qu'à être rouge.
